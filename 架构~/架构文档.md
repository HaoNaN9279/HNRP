# HNRP 架构文档

> HaoNaN Render Pipeline — 基于 Unity 2022.3 的自定义渲染管线  
> 本文档为全新架构规划，尚未实施。

---

## 0. 设计目标

| # | 目标 | 原则 |
|---|------|------|
| 1 | 可扩展 —— 轻松增加自定义 Pass | Pass 继承纯 C# 基类 + `[Pass]` Attribute 自动发现 |
| 2 | 可编排 —— Slot 连接 Pass，未来可视化编辑器 | name-based 连接配置外部化 |
| 3 | 运行时可变 —— 不同 Camera 不同管线 | Pass 非 ScriptableObject；Config 支持运行时副本 |
| 4 | Camera 隔离 —— Pass 仅作用于一个 Camera | 每 Camera 独立 CameraRenderer 实例 |
| 5 | 视图全覆盖 —— SceneView/Preview/Reflection 可独立配置 | 每种 CameraType 有默认 RenderGraphAsset 可配置 |
| 6 | 配置外部化 —— 独立参数资源 | PassConfigBase ScriptableObject 子类化 |

## 1. 总体架构概览

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                  HNRenderPipelineAsset (RenderPipelineAsset)                 │
│  ┌─ 默认 RenderGraphAsset 引用 ────────────────────────────────────────────┐ │
│  │  defaultGameRenderGraph       → RenderGraphAsset "Standard"             │ │
│  │  defaultSceneViewRenderGraph  → RenderGraphAsset "SceneView"  (Editor)  │ │
│  │  defaultPreviewRenderGraph    → RenderGraphAsset "Preview"    (Editor)  │ │
│  │  defaultReflectionRenderGraph → RenderGraphAsset "Reflection"           │ │
│  └────────────────────────────────────────────────────────────────────────┘ │
│  → CreatePipeline() → HNRenderPipeline                                      │
└─────────────────────────────────────────────────────────────────────────────┘
                              │
                              │ Camera 选管线: override → default → null
                              ▼
┌─── RenderGraphAsset (管线图模板, .asset) ──┐    ← 静态蓝图
│  PassDefinition[]                           │
│  SlotConnection[]                           │    CameraRenderer 构建时读取
│  PassDependency[]                           │    （内容连接 + 显式依赖边）
│  RenderGraphSettings                        │
└──────────────┬──────────────────────────────┘
               │ Instantiate（每 Camera 独立）
               ▼
┌──────────────── CameraRenderer ────────────────────────────────────────────┐
│  passes: List<Pass>          ← 纯运行时 C# 对象，可动态增删改               │
│  context:  CameraContext     ← Camera 专属渲染上下文                        │
│  运行时 API: AddPass<>() InsertPass<>() RemovePass() SetPassEnabled()      │
└──────────────┬──────────────────────────────────────────────────────────────┘
               │ Render() 每帧
               ▼
┌───── CameraRenderer.Render() ──────────────────────────────────────────────┐
│  1. Culling                                                                 │
│  2. 更新 GlobalConstantBuffer + Keywords                                    │
│  3. renderGraph.RecordAndExecute(遍历 passes, 依赖由 RenderGraph 自动管理)  │
│  4. 清理（Release Cmd, Pass Cleanup, EndFrame）                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 关键变化 vs 旧架构

| 旧设计 | 新设计 |
|--------|--------|
| Pass 继承 ScriptableObject | Pass 继承纯 C# 抽象类 |
| 连线通过 index (Slot.Connect) | 连线通过 name，记录在 RenderGraphAsset 中 |
| 管线定义写在 Standard/Preview.cs 代码中 | 管线定义是 RenderGraphAsset 资源 |
| 所有 Camera 共享同一组 Pass 实例 | 每 Camera 独立 CameraRenderer |
| HNRenderGraphBase 负责一切 | 职责分离给 CameraRenderer + RenderGraphAsset |

## 2. 核心组件

### 2.1 默认 RenderGraph 选择

Camera **不直接**持有管线定义，通过 `HNRenderPipelineAsset.defaultXxxRenderGraph`（按 CameraType 默认）或 `HNAdditionalCameraData.pipelineConfigOverride`（类型为 `RenderGraphAsset`）选择管线图。`RenderGraphAsset` 自带 `RenderGraphSettings`（SHEvalMode, allowHDR），是唯一的管线级配置容器。

```
Camera 选择管线（按优先级）:
  1. HNAdditionalCameraData.pipelineConfigOverride  → 最高优先
  2. HNRenderPipelineAsset.defaultXxxRenderGraph   → 按 CameraType 默认
  3. 以上都为空 → 不渲染该 Camera
```

**CameraType 分支选择**：`Reflection` → 反射渲染图；`Preview` → 名 `Preview Camera` 用 GameView 渲染图，其余（含 Unity `PreviewRenderUtility` 创建的 `Preview Scene Camera`，即材质 / 网格 / 纹理 Inspector 预览）用 PreviewView 渲染图；其余类型经视图块按 `HNAdditionalCameraData.RenderGraphViewIndex` 选择。

### 2.2 RenderGraphAsset（管线图模板）

| 字段 | 用途 |
|------|------|
| `kind: RenderGraphKind` | 模板标识 —— 运行时定位同一份模板构建代码 |
| `settings: RenderGraphSettings` | 管线级公用设置（SHEvalMode, allowHDR 等） |
| `passParameterCache: List<Pass>` | 按 pass 实例名索引的**参数缓存**（L1，`[SerializeReference]` 序列化） |

> **ADR-018（修订 ADR-016）**：pass **结构与连接**由模板构建代码
> （`RenderGraphTemplate.CreateBlueprint`）唯一生成，不写入资源；资源只保存
> `kind` + `settings` + 参数缓存。参数缓存是与模板 pass **同类型**的另一个
> pass 实例，仅承载参数值；运行时 `RenderGraphAsset.Build` 把缓存值注入模板
> 代码创建的 pass（模板默认 → 编辑器保存值，逐级覆盖）。删除缓存即回到模板
> 默认。pass 因此需要 public 无参构造（供 `[SerializeReference]` 反序列化）。

### 2.3 模板与实例

`RenderGraphAsset` 是静态模板（ScriptableObject 磁盘文件），`CameraRenderer.passes` 是运行时实例（内存 List\<Pass\>）。

| 对比维度 | RenderGraphAsset | CameraRenderer.passes |
|---------|-----------------|----------------------|
| 存储 | 磁盘 .asset | 内存 |
| 运行时修改 | ✅ 影响所有引用者 | ✅ 仅影响当前 Camera |
| 持久化 | Editor Save / Build 固定 | 不持久 |
| 用途 | Editor 编排管线 | 运行时执行 |

### 2.4 Pass 系统

Pass 是 `[Serializable]` 纯 C# 抽象类（非 ScriptableObject），结构与参数默认值由
模板构建代码创建，不作为实例序列化在资源中。关键生命周期方法：
`SetupSlots()` → `PreRecord(template, context)` → `Record(RenderGraph)` → `Cleanup()`。

**`IsEnabled` 与 Record guard 契约（ADR-021）**：`IsEnabled` 是**外部动态开关**
（编辑器面板 / `CameraRenderer.SetPassEnabled` / 运行时脚本），由宿主持有的持久
pass 实例承载，跨帧生效；Pass 内部**不得**写 `IsEnabled`。`Record` 有两种合法
提前退出时机：

- **预检**：`AddRenderPass` 之前，必需输入未连接 / 无有效句柄 / 资源缺失时直接
  `return`，不产生渲染图 pass；
- **运行期**：`SetRenderFunc` 的渲染函数内部，依据 `IsEnabled` 或帧条件 `return`。

**禁止**在 `AddRenderPass` 之后、`SetRenderFunc` 之前 `return` —— RenderGraph 在
执行期对未被裁剪且无 render func 的 pass 抛
`InvalidOperationException("... was not provided with an execute function")`。
预检跳过时，下游必须以 `IsConnected && HasHandle` 守卫输入句柄。

- **参数面**：暴露给面板的参数用 `[SerializeField]` 私有字段 + 公共属性（如
  `RendererListParams` / `ReceiveShadow`）；参数缓存（L1）与模板 pass 同类型，
  用同一套字段承载值，由 `PassParameterCopy`（外部静态工具，不进 Pass 类）拷贝。
- **构造约定**：每个具体 Pass 子类提供 public **无参构造**（默认参数初始化，
  供参数缓存的 `[SerializeReference]` 反序列化）与 public `(string passName)`
  构造（模板构建代码 / `PassRegistry` 按名创建用）。
- **逐级参数覆盖**（ADR-018）：
  L0 模板基础参数 —— 模板构建代码写死；L1 编辑器修改 —— `RenderGraphAsset`
  参数缓存，序列化保存；L2 运行时动态修改 —— CameraRenderer 的 pass 实例字段，
  不落盘。运行时 `Build` = 执行模板代码（L0）→ 按同名同类缓存注入（L1）→
  每帧实例可被外部脚本改写（L2，优先）。pass 参数默认值只在构造初始化，
  不在 `PreRecord` 中重置；`PreRecord` 仅做相机/模板级派生（如按 `AllowHDR`
  校准自建颜色格式）。

**Editor 绑定**：Pass 非 UnityEngine.Object，不能用 `[CustomEditor]`。每个 Pass 的
Editor（`PassEditor` 子类）用 `[PassEditor(typeof(XxxPass))]` 绑定，
`PassEditorRegistry`（TypeCache 扫描）映射类型 → 编辑器单例（重复绑定记 Warning，
未绑定回退 `DefaultPassEditor`）；`RenderGraphAssetEditor`
采用 CoreRP Volume 面板布局绘制 pass 列表：每 pass 一个 Header（左侧折叠箭头 +
**启用开关**（绑定 `isEnabled`，关闭则参数主体灰显）+ 标题 + 右侧 **? 帮助**（占位）
+ **三点菜单**（Reset Parameters 回复模板默认）），参数主体**直接暴露全部可修改
参数**：未修改时显示模板预设值（L0），一旦修改即自动创建参数缓存并保存（L1），
该参数 label 以**粗体**标记已覆盖；Reset 即删除缓存回到模板默认。

**面板内容的统一接口（ADR-039）**：`PassEditor` 即「各 Pass 自定义面板内容」的统一
接口，`RenderGraphAssetEditor` 展开某个 pass 时按其类型取回编辑器并调用
`DrawPassParameters(context)`（即调用该 pass 自己的绘制代码）。自定义有两个粒度：
① **声明式**——覆写 `ConfigureFieldLayout(layout)`，用 `PassFieldLayout` 声明
分组 / 隐藏 / 条件显示（`ShowWhen`）/ 条件灰显（`DisableWhen`），参数行仍由
`PassParametersGUI` 按 `SerializedProperty` 统一绘制；② **完全自定义**——覆写
`DrawPassParameters`（未覆写时按反射平铺全部可编辑字段：bool/枚举/数值/Color/Vector，
嵌套可序列化 struct 自动展开）。Pass 特异的字段隐藏规则（如 `RenderOutputPass.flip`
由相机上下文驱动）由该 pass 的 `PassEditor` 声明，通用抽屉不内建任何具体 Pass 的字段
黑名单；参数无 Pass 级可调项的 pass 也在面板内说明其参数来源。当前实现自定义面板的
pass：`DrawShadowPass`、`ForwardPass`、`ClusterCullingReflectionProbePass`、
`RenderOutputPass`、`BuiltinSkyPass`、`BuildLightDataPass`、`ClusterCullingLightPass`、
`EditorWireOverlayPass`。SlotConnections 与 PassDependencies 为纯模板代码产物，不显示在面板。

**Slot 类型**：`TextureSlot` / `ComputeBufferSlot` / `RendererListSlot`，各有 Input / Output 方向。**Slot 只表达内容资源句柄**（当前实际使用者为 color / depth 链）；不再兼任执行依赖或全局资源传递（ADR-041）。

**Handle 传递**：Output Slot 创建资源（`renderGraph.CreateTexture`）并持有 Handle；Input Slot 通过 `ConnectedSlot.Handle` 读取。RenderGraph 自动根据声明的读写推导依赖顺序。

**显式依赖边 `PassDependency`（ADR-041，修订 ADR-023）**：不携带任何资源句柄，只表达「SourcePass 先于 TargetPass 执行」与「TargetPass 可发现 SourcePass 作为生产者」。`RenderGraphBlueprint.Dependencies` 声明；`RenderGraphBuilder` 注入到 `Pass.Dependencies` 并参与拓扑排序。`ForwardPass` 等消费者与生产者（`BuildLightDataPass` / `ClusterCullingLightPass` / `ClusterCullingReflectionProbePass` / `DrawShadowPass`）之间**不再连 slot**，改由依赖边连接。

**全局 shader 资源绑定（ADR-023 / ADR-041）**：产出 shader 全局资源的 Pass（同上四者）实现 `IGlobalShaderResource`，在 `BindGlobalShaderResources(cmd)` 中自行决定绑定哪些属性（buffer / texture / 常量缓冲）、使用哪个全局 keyword、以及何时算「可用」——不可用（被禁用 / 本帧未产出）时须主动关闭对应 keyword。全局资源为 **Pass 自持的持久资源**（见 §2.8），生产者 render func 在 Record 期写入、执行期上传。`ForwardPass` 作为消费者不再硬编码任何生产者类型与属性 ID：绘制前遍历自身 `Pass.Dependencies` 中实现该接口者，去重后各调用一次。绑定时机仍在消费者 draw 前，保持「帧内全局状态统一设置」的确定性；依赖边已保证生产者先于消费者执行。该「上游生产者发现」由统一原语 `ConnectedProducerQuery.CollectOwners<T>` 完成（零分配、引用去重）。

**跨 pass 语义（R / F / G，ADR-040）**：slot 句柄只表达「资源存在」，不表达「内容为何」。资源内容语义经 **R 通道**（`PassSlot.Traits`，特征契约）随句柄发布与透传；与资源无关的帧状态经 **F 通道**（`CameraContext.Facts`）发布；图级配置经 **G 通道**（`RenderGraphSettings`）对 `PreRecord` 可见。消费者据此决策，而非从 `IsConnected` / `HasHandle` 推断。详见 §2.10。

**Slot 句柄重置**：`CameraRenderer.Render` 每帧先对**全部** pass（含被禁用者）调用 `ResetSlotHandles`，再执行启用 pass 的 `PreRecord` / `Record`；避免禁用 pass 残留上一帧输出句柄被下游误判为「本帧已产出」。

**`[Pass]` Attribute**：继承 Pass 的类加 `[Pass("Name")]` 即被反射自动发现，无需手动注册。

**注册策略**：Editor 中反射扫描程序集 → Build 时 `PassRegistryGenerator` 生成硬编码注册表 → Player 中零反射。

### 2.5 PassConfigBase（Pass 统一参数接口）

每个 Pass 拥有一套 `PassConfigBase` 子类 ScriptableObject，集中存放该 Pass 的全部参数（资源引用 + 可调数值 + Volume 开关）。Editor 面板、运行时代码、Volume 系统都通过它操作 Pass。

**运行时副本**：`ScriptableObject.Instantiate(def.Config)` 为每个 Camera 创建独立副本。同一资产被多个 Camera 引用时互不干扰。

### 2.6 CameraRenderer

持有 `List<Pass>`。核心 API：

| 方法 | 用途 |
|------|------|
| `AddPass<T>(name, connections)` | 追加 Pass + 声明连接 |
| `InsertPass<T>(index, name, connections)` | 插入到指定位置 |
| `RemovePass(name)` | 移除 Pass + 断开连接 |
| `FindPass<T>(name)` | 按名称查找 |
| `GetConfig<T>(name)` | 获取运行时 Config 副本 |
| `SetPassEnabled(name, enabled)` | 开关 |
| `Connect()` / `Disconnect()` | 运行时插断连线 |
| `Reset(newTemplate)` | 回到模板初始状态 |
| `Facts` | 本相机跨帧持有的帧级事实板（F 通道，见 §2.10） |

**Render 流程**：Culling → 全局状态 → `renderGraph.RecordAndExecute(遍历 passes, 无需排序)` → Cleanup + `EndFrame()`。

**宿主与生命周期（ADR-019）**：`CameraRenderer` 不再由全局"按相机 id"缓存持有，而是挂在相机的 `HNAdditionalCameraData` 组件上（`GetOrCreateRenderer`），生命周期 = 相机组件。`CameraRenderer` 不持有 `CameraContext`：`Render(renderGraph, cameraContext)` 以参数接收每帧上下文，避免跨帧悬挂已释放的帧对象。反射探针面渲染的池化相机同样通过其 `HNAdditionalCameraData` 持有 renderer。

> AddPass/RemovePass 开销非零，不应每帧高频调用。
>
> 同一模板引用上的参数改动由 `RenderGraphAsset.ParameterRevision` 追踪（ADR-022）：修订号变化时 `Build` 重建 pass 列表，避免仅比较引用相等导致参数不生效。

### 2.7 CameraContext（单 Camera 上下文）

持有当前 Camera 的 Culling 结果、VisibleLights、VisibleReflectionProbes、CommandBuffer、GlobalConstantBuffer、Frustum 等。每 Camera 独立，解决旧架构中 RenderingData 被共享的 bug。**纯帧级**：每相机每帧创建、帧末 `Dispose`；`CameraRenderer` 不持有它，避免跨帧引用已释放的帧对象（ADR-019）。

### 2.8 资源生命周期

| 类型 | 创建 | 释放 | 管理方 |
|------|------|------|--------|
| **Transient** | `renderGraph.CreateTexture/CreateComputeBuffer`（Pass 内部） | 自动 (first write → last read + EndFrame) | RenderGraph |
| **Imported** | `renderGraph.ImportTexture/ImportBackbuffer` | 手动 `RTHandles.Release` | 开发者 |
| **Persistent（跨帧）** | Pass 懒分配（`RTHandles.Alloc` 阴影 / 探针 atlas；`HNRenderPipelineUtils.ValidateComputeBuffer` 或 `new ComputeBuffer` 光照数据 / 簇剔除掩码 / 探针数据缓冲；及 `TextureAllocator` / 驻留表） | `Pass.Cleanup`（模板重建或宿主相机销毁时） | 使用它的 Pass 实例 |

**持久资源归属（ADR-020）**：跨帧 GPU 资源**随使用它的 Pass 实例**，不做管线级共享上提。`Pass` 实例由宿主相机（`HNAdditionalCameraData`）持有并跨帧复用，因此 `DrawShadowPass` / `ClusterCullingReflectionProbePass` 的 atlas、`TextureAllocator`、驻留表，以及 `BuildLightDataPass` / `ClusterCullingLightPass` / `ClusterCullingReflectionProbePass` 的全局缓冲（光照数据 / 簇剔除掩码 / 探针数据）均可跨帧保留；`TextureAllocator` 按使用者实例化，便于多处复用。相机销毁（组件 `OnDestroy`）时释放对应资源。多相机暂不共享 atlas。

**准则**（ADR-017 / ADR-020 / ADR-041）：
- **Transient** 渲染资源由 **Pass 自身拥有**：Pass 消费已连接的输入槽；输入槽未连接或句柄无效时，用自身参数（`TextureResourceParams` / `RendererListParams`）自建资源并输出到 slot。
- **Persistent（全局资源）** 由生产者 Pass 自持，不经 slot 传递：光照数据缓冲经 `ILightDatasProvider` 暴露给 compute 消费者（`ClusterCullingLightPass`），其余经 `IGlobalShaderResource` 全局绑定给 `ForwardPass`。
- `Pass.Record()` 中 **Transient** 资源一律通过 RenderGraph API 创建，**严禁** `new ComputeBuffer()` / `new RenderTexture()`；**Persistent** 资源经 `RTHandles.Alloc` / `ValidateComputeBuffer` 懒分配（在 `Record` 内确保分配，随实例跨帧复用）。
- `Pass.Cleanup()` **仅释放 Imported 与 Persistent 资源**；Transient 由 RenderGraph 托管。
- `renderGraph.EndFrame()` 在 `RecordAndExecute` 后调用，触发死资源回收。

### 2.9 资源参数（并入 Pass）

独立的 `ResourceDefinition` / `ResourceNode` / `ResourceConnection` 层已移除。渲染资源参数以**值类型 struct** 内嵌在 Pass 上：

| 参数类型 | 字段 | 用途 |
|------|------|------|
| `TextureResourceParams` | 颜色格式 / 深度位 / 缩放 / 固定尺寸 / 过滤 / 包裹 / 维度 / mipmap / 清空 | 纹理分配（`CreateDesc` → `renderGraph.CreateTexture`） |
| `RendererListParams` | 队列范围 / 渲染层掩码 | 渲染器列表构建（`CreateDesc` → `renderGraph.CreateRendererList`） |
| `IResourceTraits`（特征派生契约，如 `IDepthPrepassTraits`） | 资源内容语义（R 通道）：契约与不可变实现均由特征定义 | 生产者 `SetHandle(handle, traits)` 发布，消费者经 `PassSlot.Traits` + `is` 查询 |

- 序列化：Pass 的 `[SerializeField]` 字段，随 RenderGraphAsset 的 `[SerializeReference] List<Pass>` 一起持久化。
- 语义：输入槽**未连接**或 `HasHandle == false`（句柄无效）时，Pass 自建资源——例如 `ForwardPass` 作为颜色链头自建 ColorBuffer / DepthBuffer，`transparency` 自建透明渲染器列表。注意反射探针图集例外：它由 `ClusterCullingReflectionProbePass` **持有**（持久 `RTHandles.Alloc`，导入渲染图后写入），不经 `renderGraph.CreateTexture` 自建（见 §5.2）。全局 shader 资源（光照 / 阴影 / 探针 / 簇剔除掩码）**不经 slot**，由生产者持久持有、经依赖边 + 全局绑定传递（ADR-041）。
- 零装箱：`PassSlot<T>` 直接存储值类型 handle；渲染循环无 `object` 装箱。
- 运行时零 GC：每帧数组 / List 复用（scratch buffers），render function 闭包只捕获 `this`。

### 2.10 跨 Pass 信息传递（R / F / G 三通道，ADR-040）

Pass 之间**不得**从 slot 连接状态推断语义：`IsConnected` 只表示结构连线，
`HasHandle` 只表示「本帧产出过资源」，两者都不表达「资源内容是什么」。
跨 pass 信息一律走三条显式通道。核心只拥有**传输**，**契约与载荷归特征所有** ——
新增语义 / 事实不修改任何中心类型。

| 通道 | 载体 | 语义 | 写 → 读 |
|------|------|------|---------|
| **R** 资源语义 | `PassSlot.Traits`（根契约 `IResourceTraits`） | 单个资源的内容是什么、覆盖什么 | 生产者 `SetHandle(handle, traits)` → 消费者经 `PassSlot.Traits` + `is` 查询 |
| **F** 帧级事实 | `CameraContext.Facts`（`PassFrameFacts`，板由 `CameraRenderer` 跨帧持有） | 本帧整体状态，与具体资源无关 | 管线 / pass `Publish(fact)` 或写强类型字段 → 其后拓扑顺序的 pass 读取 |
| **G** 图级设置 | `RenderGraphSettings` | 构建期固定的图级配置 | 模板代码 → `PreRecord(template, ...)` |

**契约由特征拥有**：每个语义 / 事实 = 一个派生接口（如 `IDepthPrepassTraits`、
`IReflectionProbeUpdateSource`）+ 特征自己的实现。核心只认根标记，永不枚举内容。

- **R（资源语义）**：`IResourceTraits` 的实现必须**不可变**（描述资源内容属性，
  如覆盖掩码，而非每帧状态）；生产者可在构造期创建一次、长期复用，稳态零分配。
  每 slot 只存 1 个引用，未声明语义即为 `null`（按需付费，不随语义数量变胖）。
- **F（帧级事实）**：混合形态。真·全局、几乎每图都用的状态（`IsPreviewCamera`）
  用强类型字段；生产者特有、图可能用不到的事实走注册区
  （`Publish` / `TryGetFact<T>`），未发布即零存储、零分配。事实板由宿主
  `CameraRenderer`（每相机）**跨帧持有**，注册区数组一次分配长期复用（严格零 GC）；
  `CameraContext` 构造时绑定并清空该板（绑定即清空，不残留上一帧事实）。

**规则**：

1. 任何跨 pass 语义必须走 R/F/G，禁止从连接 / 句柄存在性推断。
2. R 优先 —— 能用资源语义表达就不上帧级黑板。
3. F 事实随帧（`CameraContext` 绑定时清空）；由 pass 发布的 F 事实必须伴随
   `PassDependency`（显式依赖边）以保证拓扑顺序。
4. 禁止跨帧缓存 R/F（pass 实例跨帧存活，缓存即状态残留）。
5. 契约用不可变引用（R）/ 引用型接口（F），禁止装箱、泛型字典与 enum 作泛型参数
   （Mono native crash 已知问题）；R 实现不可变，F 注册区惰性分配、稳态复用。
6. **仅透传句柄的 pass 必须同时透传 `Traits`**（如 `BuiltinSkyPass` /
   `EditorWireOverlayPass`），否则下游丢失语义。
7. 消费端决策落 GPU 状态（keyword / 材质属性 / `RenderStateBlock`）时，
   必须携带在自己的 render func 内。

**首个消费者（PreZ 复用）**：`DepthOnlyPass` / `DepthNormalPass` 在深度输出上发布
`IDepthPrepassTraits`（覆盖范围 = 本 pass 渲染层掩码，不可变实例、掩码变化才重建）；
`ForwardPass` 查询该契约，仅在「不透明列表 + 覆盖本 pass 渲染层」时用
`ZTest Equal` / `ZWrite Off`（经 `RendererListDesc.stateBlock` 覆盖材质状态）
复用预渲染深度、减少 overdraw，并把深度目标改为只读、继续透传该契约；
不满足条件时回退读写深度。

**生产者发现**：`ConnectedProducerQuery.CollectOwners<T>` 是按 `Pass.Dependencies`
（显式依赖边注入）发现生产者（上游 pass 实现某契约，如 `IGlobalShaderResource` /
`ILightDatasProvider`）的统一原语，零分配、引用去重。不再从 slot 连接推断。

## 3. 默认管线示例

### Standard（前向渲染管线）

```
Pass 列表:
  buildLight        BuildLightDataPass
  drawShadow        DrawShadowPass
  clusterProbe      ClusterCullingReflectionProbePass
  clusterLight      ClusterCullingLightPass
  depthNormal       DepthNormalPass
  screenSpaceShadow ScreenSpaceShadowMaskPass（compute 合并全部投影光源 → mask）
  forwardOpaque     ForwardPass（不透明，自建 ColorTarget）
  sky               BuiltinSkyPass
  transparency      ForwardPass（透明）
  wireOverlay       EditorWireOverlayPass
  finalBlit         RenderOutputPass

内容连接（color / depth / mask 链，RenderGraph 托管）:
  depthNormal.DepthTargetOutput → forwardOpaque.DepthTarget（预渲染深度，供后续 pass 复用；法线输出暂未消费）
  depthNormal.DepthTargetOutput → screenSpaceShadow.DepthTarget
  screenSpaceShadow.ShadowMaskOutput → forwardOpaque.ScreenSpaceShadowMask
  forwardOpaque.Color/DepthTargetOutput → sky → transparency → wireOverlay → finalBlit

显式依赖边（全局资源生产者 → 消费者，不携带句柄）:
  buildLight → clusterLight（经 ILightDatasProvider，compute SRV）/ forwardOpaque / transparency
  drawShadow → forwardOpaque / transparency / screenSpaceShadow（经 IShadowMapProvider 取 atlas + 表）
  clusterProbe → forwardOpaque / transparency
  clusterLight → forwardOpaque / transparency
```

执行顺序由 RenderGraphBuilder 按「内容连接 ∪ 显式依赖边」拓扑排序，passes 列表即拓扑序；RenderGraph 执行期对无资源依赖的 pass 保持插入顺序。

> **DepthOnlyPass** 提供「只绘制不透明物体深度」的独立能力（shader `DepthOnly` LightMode，
> 深度写深度目标、无颜色输出），当前未接入任何模板，供自定义渲染图使用；其深度经输出 slot 供下游连接。
> **DepthNormalPass** 用 shader `DepthNormal` LightMode 把深度与法线分别绘制到深度 / 法线两张目标
> （法线编码为 `normalWS * 0.5 + 0.5`），输入未连接时按自身 `TextureResourceParams` 自建，
> 解析出的两个句柄分别经 `DepthTargetOutput` / `NormalTargetOutput` 发布。
> 深度目标为**纯深度纹理**（`ColorFormat = None` + `DepthBits`），使深度可作为着色器资源被
> 采样（供 `ScreenSpaceShadowMaskPass` 的 compute 读取）；非深度纹理保持配置的颜色格式。

**ScreenSpaceShadowMaskPass（屏幕空间阴影，ADR-042）**：用 ComputeShader 把当前视锥内
**所有投影光源**（主方向光 + 其他方向光 + 点光 + 聚光）的可见性逐像素合并绘制到一张单通道
`R8_UNorm` mask（UAV 随机写入），经 `ShadowMaskOutput` 接入 `ForwardPass`。深度经内容 slot
消费 `DepthOnlyPass` / `DepthNormalPass` 输出；阴影图集与三张表经显式依赖边发现
`IShadowMapProvider`（`DrawShadowPass`），用其既有全局绑定。`ForwardPass` 连接该 slot 时
绑定 `_ScreenSpaceShadowMask` 全局纹理并开启 `SCREEN_SPACE_SHADOW_MAP`（透明度 pass 未连接，
自动关闭并回退逐光源 atlas 阴影）。mask 语义：1 = 完全受光，0 = 被任一投影光源完全遮挡；
多光源可见性相乘合并。生产端不可用时预检跳过，mask slot 无句柄，下游回退 atlas 阴影。

## 5. Cluster Culling / 反射探针 / 光照

核心算法逻辑保留，重构点：
- Pass 基类迁移到纯 C# `Pass`
- 实例状态（`catchedProbeCount` 等）移到每帧 `PassData`
- ComputeShader 通过 `CameraContext.RuntimeResources` 引用

### 5.1 Realtime Probe（实时反射探针渲染）

实时反射探针在所有主相机渲染之前渲染（`HNRenderPipeline.Render` Phase B）：

| 环节 | 实现 |
|------|------|
| 收集 | Phase A 剔除所有相机后，从 `CullingResults.visibleReflectionProbes` 筛 `mode == Realtime` 的 probe。`VisibleReflectionProbe` 仅暴露私有 `m_InstanceId`，经反射读取 + `Resources.InstanceIDToObject` 取组件 |
| 面策略 | 按 `probe.timeSlicingMode`：`AllFacesAtOnce` 每 6 帧全 6 面（相位按 instanceId 偏移）；`IndividualFaces` 每帧 1 面轮转；`NoTimeSlicing` 每帧全 6 面 |
| refreshMode | `EveryFrame` 每帧更新；`OnAwake` 首次渲染后跳过（`MarkInitialized`）；`ViaScripting` 不自动渲染 |
| 渲染 | 每面取池化相机（`RealtimeProbeCameraPool`，`cameraType=Reflection`），位于 probe 位置、朝向对应面，`targetTexture = probe.realtimeTexture`；`CameraContext.TargetId = RenderTargetIdentifier(realtimeTexture, 0, face)`；走 `CameraRenderer.Build(DefaultReflectionRenderGraph)` 完整流程 |
| 去重 | 池记录本帧已渲染 `(probeId, face)`，多相机可见同一 probe 只渲染一次 |
| 输出 | `RenderOutputPass` 检测 `UsesCustomTarget`，经 `ImportBackbuffer(face)` 写入 cubemap 面 |

Reflection 渲染图模板不含 Cluster Culling Probe pass —— 渲染 probe 面时不再渲染反射探针。

### 5.2 反射探针图集（ClusterCullingReflectionProbePass）

探针 cubemap 经 `Blitter.BlitCubeToOctahedral2DQuadWithPadding` 以八面体投影写入一张 **`Tex2DArray` 图集**，位置由 `TextureAllocator` 分配（与阴影 atlas 同机制，ADR-020/027），内容按需更新（ADR-028）。

| 环节 | 实现 |
|------|------|
| 参数 | 单 slice 分辨率 `atlasSliceResolution`（默认 2048）、`atlasSliceCount`（默认 2）；分辨率收敛到 [256, 2048]，slice 收敛到 [1, 2] |
| 上限来源 | `TextureAllocator` 要求 `textureResolution / minBlockSize <= 8`，而 brick 必须为 256（满足 `ReflectionProbe256`）⇒ 单 slice ≤ 2048；容量不足时用多 slice 扩容 |
| 分配 | 每帧收集可见探针 → 按 `importance` 降序 + 实例 id 升序排序 → 与驻留集合 diff（新增 / 分辨率变化 `Release + Allocate`）→ 不再可见立即 `Release` |
| 槽位 | `TextureAllocatorResult.ScaleOffset`（相对单 slice 归一化）写入 `ClusterCullingReflectionProbeDatas.scaleOffset`，`SliceIndex` 写入同结构的 `sliceIndex`（shader 按 slice 采样） |
| 顺序约束 | 分配可能触发重组搬移既有块，故槽位偏移必须**在全部完成分配后**统一回读（`Contains + TryGetResult`），不可边分配边写 |
| 内容复用 | 逐探针 `ProbeSlot` 记录「槽位 + 源纹理 + 块尺寸 + 内容有效性」；本次分配过 / 槽位或源变化 / 内容失效 / 实时探针被重渲染 ⇒ 重写，否则跳过：baked / custom 写入一次即跨帧复用，实时探针由 `IReflectionProbeUpdateSource`（`ReflectionProbeRenderer`，以相机池「本帧已渲染面」为准）判定，无信号时保守每帧重写 |
| 槽位复用 | 「本帧执行过 `Allocate`」必须置脏，不能只比较偏移：槽位释放后可被其它探针写入，本探针再拿回同一偏移时会采到残留 |
| 图集尺寸 | `allocatedResolution` 经 `_ClusterCullingReflectionProbeParamsBuffer` 上传（`atlasSize`），shader 侧 `GetReflectionProbeAtlasUV` 据此归一化 texel padding |
| shader | `TEXTURE2D_ARRAY(_ReflectionProbeAtlas)` + `SAMPLE_TEXTURE2D_ARRAY_LOD(tex, sampler, uv, sliceIndex, mip)`；逐探针 `mipCount = log2(块尺寸) - 2` 限制 mip 范围 |
| mip | 逐 mip 直接由源 cubemap 投影（`_BlitMipLevel`，源无 mip 时钳到 0），只对重写的探针生效；图集以 `useMipMap: true, autoGenerateMips: false` 分配，**不使用**整图 `GenerateMips`。级数 = `log2(块尺寸) - 2`（尾部两级 padding 会吃掉整块，不再生成），`mipCount` 用同一值 |

## 6. 阴影

`DrawShadowPass` 把所有光源阴影绘制到一张 `Texture2DArray` atlas，位置由 `TextureAllocator` 分配；每光源与每 atlas 槽的元数据分两张结构化缓冲（`_ShadowLightDatas` / `_ShadowMapDatas`）供 GPU 两级查表。

| 环节 | 实现 |
|------|------|
| 归属 | 级联配置（级数 / 分割 / 更新模式）默认随**相机**（`HNAdditionalCameraData.shadowSettings`）；方向光可经 `HNAdditionalLightData.overrideCameraShadowSettings` 用自身设置覆盖；分辨率随**光源**（`HNAdditionalLightData.cascadeResolution`）；单张 map 分辨率在运行时按生效级数收敛（`CascadeShadowUtils.ClampResolution`） |
| 矩阵 | 方向光手写：用相机子视锥拟合球体后绕光方向建正交投影（透视 / 正交相机共用同一 split 语义，`CalculateFrustumCorners` 均在给定距离取平面）；点 / 聚光用 `CullingResults.Compute*ShadowMatricesAndCullingPrimitives` |
| 选级 | shader 按**片段视轴深度**与 splits 判定（`_ShadowCameraDatas`，按方向光槽位索引的 StructuredBuffer<`ShadowCameraData`>，经 `ShadowLightData.cameraDataIndex` 定位），**不再使用拆级裁剪球**；C# 侧对应 split `[near_i, far_i)` 与深度判据互为镜像 |
| 级间衔接 | 本级远端最后 `_ShadowCascadeBlend`（占分割距离百分比，`DrawShadowPass.cascadeBlendPercentage`，默认 0.1）为过渡区：`smoothstep` 求权重，`InterleavedGradientNoise` 逐像素在「本级 / 下一级」二选一，每像素仍只采一级 cascade（采样数不变），消除硬拼接缝（ADR-038） |
| 更新 | `EveryFrame` 全量重绘；`OnDemand` 经 `RequestShadowUpdate`；`Custom` 按每级帧间隔 + 稳定相位错帧 |
| 绘制 | 逐 map 局部清远深度 + 用 `ScriptableRenderContext.DrawShadows` 直接画投射者（取引擎按光源收集的投射者集合，避免漏掉视锥外投射者）；方向光剔除体取组级 `ShadowSplitData`；投射者顶点做 **shadow pancaking**（`LitShadowCaster.hlsl` 把近平面之前的顶点钳到近平面，与 URP `ShadowCasterPass` 一致），防止视锥外大物体被光源近平面部分裁剪 |
| 生命周期 | atlas / 分配器 / 驻留表随 `DrawShadowPass` 实例（每相机）跨帧保留，见 ADR-020 |
| SceneView 同步 | 级联随相机（ADR-024），而 SceneView 相机无法被用户配置，故 `HNAdditionalCameraData.GetEffectiveShadowSettings()` 在 Editor 下让 SceneView 相机**跟随主游戏相机**（`Camera.main` 优先，其次首个启用的 Game 相机，结果缓存、失效重查），无来源时退回自身设置；阴影 pass 与 `ResolveMaxShadowDistance` 统一走该入口，保证 Scene View 与 Game View 阴影一致 |

### 6.1 传统 PCSS 软阴影（ADR-037）

逐 light 可选硬 / 软：`HNAdditionalLightData.shadowType`（Hard/Soft）+ `penumbraRadius`（float 0–9，光源尺寸，texel 半径的 log2）。pass 的 `softShadowEnabled` 总开关关闭时软光退回硬路径。

| 环节 | 实现 |
|------|------|
| 深度图格式 | **单张** `GraphicsFormat.R16_UNorm`，只存归一化线性深度，**无深度平方、无 mip、无深度附件**。投射者用 `BlendOp Min` 直接保留最近深度（深度单调，逐通道 min 正确），区域复位由 `ShadowClear` 覆盖写 1。软 / 硬共用同一格式，**软硬切换不再重建 atlas** |
| 内存 | 单通道 4096² 约 33.5MB/slice（原软模式 RG16F+mip 约 89MB、硬模式约 67MB） |
| 深度偏置 | 无深度附件，`SetGlobalDepthBias` 失效，自阴影由采样端 `_ShadowDepthBias`（归一化线性深度单位）抑制 |
| 线性深度 | 方向光：正交裁剪 z（按 `UNITY_REVERSED_Z` 归一）；点 / 聚光：`length(worldPos-lightPos)/range`。投射者（`LitShadowCaster`）与采样端（`Shadow.hlsl`）同式，光源位置 / range 经 `ShadowLightData.lightPosRange` 提供 |
| PCSS Step1 | blocker 搜索：在最大半影核（光源尺寸 = `2^penumbraRadius` texel，cap 到 `_ShadowMaxFilterRadius`）内用**旋转泊松盘**采样，逐 texel 深度比较（CoreRP `sampler_PointClamp`），取遮挡样本平均深度。核内无遮挡样本 ⇒ 直接返回完全受光 |
| PCSS Step2 | 半影估计：`separation = receiverDepth − avgBlocker`；方向光 `separation × 2^r`，点 / 聚光 `separation/avgBlocker × 2^r`；乘 `_ShadowSoftness` 后 clamp 到 `[_ShadowMinFilterRadius, maxRadius]`（contact hardening） |
| PCSS Step3 | 滤波：在该半径的旋转泊松盘内做 PCF（逐 texel 比较 `receiverDepth <= storedDepth`），可见性 = 命中比例 |
| 旋转泊松 | 16 点泊松盘 LUT（Bridson 生成，单位圆，最小间距 ≈ 0.356）；旋转角 = CoreRP `InterleavedGradientNoise(screenUV × _ScreenParams.xy, 0) × 2π`（静态，无 TAA 时不闪烁）。blocker / filter 采样数由 `_ShadowBlockerSampleCount` / `_ShadowFilterSampleCount` 下发（LUT 前 N 个，默认 8 / 16） |
| atlas 区域约束 | 所有采样 UV clamp 到本 map 的 `scaleOffset` 区域内，防软核越界读到其它 light 槽位 |
| 软阴影调试 | `HN_DEBUG_PER_PIXEL` 下每像素通道 `ShadowFilterRadius`（`ForwardPass` 通道 18 / `LitDebug.hlsl` `HN_LIT_DEBUG_SHADOW_FILTER_RADIUS`）：显示本像素 PCSS 实际使用的滤波半径（texel）。值由 `Shadow.hlsl` 全局 `_HNRPShadowDebugPcss` 在 `SamplePcss` 内写入，`Lit.hlsl` 每像素起始置 0 |
| 硬阴影 | 单通道深度图 3×3 点采样 PCF（`SampleShadowHard`），软硬由逐 map 的 `shadowParams.y` 在片元内分流 |
| 参数 | 全局 8 float `_ShadowMapParamsBuffer`：`_ShadowSliceResolution / _ShadowDepthBias / _ShadowSoftness / _ShadowMinFilterRadius / _ShadowMaxFilterRadius / _ShadowBlockerSampleCount / _ShadowFilterSampleCount / _ShadowCascadeBlend` |
| 面板 | `HNRenderPipelineLightUI.ShadowsContent`：Enable Shadow 后绘制 Shadow Type 下拉；仅 Soft 显示 Penumbra Radius |
| keyword | 仅 `SHADOW_MAP`；Soft/Hard 由 `shadowParams.y` 分流，无独立 keyword |

### 6.2 屏幕空间阴影 mask（ADR-042）

`ScreenSpaceShadowMaskPass` 用 ComputeShader（`ScreenSpaceShadowMaskCS`，kernel `ScreenSpaceShadowMaskCS`，`numthreads(8,8,1)`）逐像素求当前视锥内**全部投影光源**的合并可见性。

| 环节 | 实现 |
|------|------|
| 输入深度 | 内容 slot `DepthTarget` ← `DepthNormalPass` / `DepthOnlyPass` 的 `DepthTargetOutput`。深度目标为纯深度纹理（`ColorFormat = None`），compute 以 `TEXTURE2D` + `sampler_PointClamp` 采样 |
| 输入阴影 | 显式依赖边 `drawShadow → screenSpaceShadow`；`ConnectedProducerQuery.CollectOwners<IShadowMapProvider>` 发现 `DrawShadowPass`，调用其 `BindGlobalShaderResources` 绑定 atlas / `_ShadowLightDatas` / `_ShadowMapDatas` / `_ShadowCameraDatas` / `_ShadowMapParamsBuffer` |
| 光源遍历 | `for i in [0, _SSShadowLightCount)` 读 `_ShadowLightDatas[i]`，`resolution <= 0` 跳过；方向光（type 1）按级联、点光（type 2，方向 = `normalize(lightPos − posWS)`）按 cubemap 面、聚光（type 3）单张。逐光源调用 `Shadow.hlsl` 的 `GetShadowAttenuation` 并相乘 |
| 世界坐标 | `ComputeWorldSpacePosition(screenUV, rawDepth, unity_MatrixInvVP)`（`ShaderVariablesGlobal` b0）|
| 输出 | 单通道 `R8_UNorm`，`EnableRandomWrite = true`，经 `ShadowMaskOutput` slot 发布；RG transient，`builder.WriteTexture` |
| 合并语义 | 逐光源可见性**相乘**：1 = 完全受光，0 = 被任一投影光源完全遮挡（近似，无法区分逐光源贡献） |
| 预检 | 深度未连接 / 无句柄、compute shader 缺失、`IShadowMapProvider.ShadowMapProduced == false` 时 `AddRenderPass` 前 return（ADR-021）|
| 消费 | `ForwardPass` 输入 slot `ScreenSpaceShadowMask`；连接时 `SetGlobalTexture(_ScreenSpaceShadowMask)` + `EnableShaderKeyword(SCREEN_SPACE_SHADOW_MAP)`，未连接（透明度 pass、预览图）时关闭 keyword 回退 atlas。`Light.hlsl` 在 keyword 下把逐光源 `shadowAttenuation` 置 1，`LitLighting.hlsl` 把合并 mask 一次施加到全部直接光照（间接光照不受影响）|
| 朝向 | compute 以「纹理原始行」写入 mask（第 r 行 = 第 r 行片元，与深度附件同向）；`ShadowInput.hlsl` 的 `SampleScreenSpaceShadowMask` 在 `UNITY_UV_STARTS_AT_TOP`（D3D）下把 `normalizedScreenSpaceUV.y` 翻回原始行列再采样，避免上下颠倒 |
| keyword | `SCREEN_SPACE_SHADOW_MAP`（由 `ForwardPass` 按 slot 连接状态开关；`DrawShadowPass` 不再触碰该 keyword）|

> 说明：单通道 mask 为多光源**合并近似**；逐光源精确需改为按光源槽索引的 `Texture2DArray`（每个 slice 一个光源的屏幕空间阴影），当前未采用。

后处理仍为预留槽位：新增只需继承 `Pass` + `[Pass]` → 在 RenderGraphAsset 中添加定义 + 连线，无需修改管线代码。

## 10. 设计决策记录 (ADR)

| # | 决策 | 理由 |
|---|------|------|
| 001 | Pass 为纯 C# 类 | 支持运行时创建/销毁；按 Camera 独立实例化 |
| 002 | 管线图外部化为 RenderGraphAsset | 配置与代码分离；支持未来可视化编辑器 |
| 003 | Pass 连线用名称匹配 | 编辑器友好；易调试 |
| 004 | 每 Camera 独立 CameraRenderer | 状态隔离；宿主见 ADR-019 |
| 005 | 用 Unity RenderGraph 模块 | 自动资源管理、Pass 裁剪、依赖推导 |
| 006 | Camera 直接引用 RenderGraphAsset，不设 Config 中间层 | 原方案 CameraPipelineConfig 仅包一个 RenderGraph 引用 + 空壳 SettingsOverride，属过度设计；per-camera 设置放 AdditionalCameraData |
| 007 | PassConfigBase 为独立 ScriptableObject | 参数设置独立于管线定义 |
| 008 | Cluster Culling | 更精细的 Z 轴裁剪 |
| 009 | Reflection Probe Octahedral → 2D Atlas | 避免 Cubemap 采样开销，支持 Mip |
| 010 | GlobalConstantBuffer 统一管理 | 减少 SetGlobal 调用 |
| 011 | RenderGraphAsset 模板, passes 实例 | 结构定义与运行时执行分离 |
| 012 | [Pass] Attribute 反射自动发现 | 零注册，继承即用 |
| 013 | 不自行实现拓扑排序 | RenderGraph 自动根据资源读写推导 |
| 014 | Transient 资源全权交 RenderGraph | 不手动 new 资源；Cleanup 仅释放 Imported 资源 |
| 015 | PassConfig 为 Pass 统一参数接口 | 所有系统通过 Config 操作 Pass；每 Camera 独立副本 |
| 016 | 移除 PassDefinition 层，Pass 直存 RenderGraphAsset | Pass 自身 `[Serializable]` + 参数 `[SerializeField]`，`CreateRuntimeClone` 克隆；编辑器用 `[PassEditor]` 绑定 + `PassEditorRegistry` 映射，预设定义在 PassEditor 下（Editor-only） |
| 017 | 渲染资源并入 Pass，移除独立 Resource 层 | `ResourceDefinition/Node/Connection/Preset` 整套移除；资源参数（`TextureResourceParams`/`RendererListParams`）内嵌 Pass；输入槽未连接或句柄无效时 Pass 自建资源并输出到 slot；每帧数组/闭包复用保证 0GC |
| 018 | Pass 参数三级覆盖（修订 016） | pass **结构与连接仍由模板构建代码唯一生成**（方案 X）；RenderGraphAsset 只存 `kind` + `settings` + 参数缓存（`[SerializeReference] List<Pass>`，同类型 pass 实例仅承载参数）。编辑器经 `PassEditor` 编辑缓存并保存；运行时 `Build` 注入同名缓存值。Pass 增加 public 无参构造以支持缓存反序列化；Pass 内不加拷贝函数（`PassParameterCopy` 外部反射拷贝） |
| 019 | CameraRenderer 宿主 = `HNAdditionalCameraData`（删除 `CameraRendererCache`） | 每相机状态由相机附加数据组件持有，生命周期 = 相机组件，无全局 id 字典、无悬挂 `CameraContext`；反射探针面用池化相机的附加数据。参照 URP `UniversalAdditionalCameraData.scriptableRenderer` |
| 020 | 持久渲染资源随使用它的 Pass 实例 | 阴影 atlas / `TextureAllocator` / 驻留表留在 `DrawShadowPass`，不上提管线、不引入管理类；`TextureAllocator` 按使用者实例化以便复用；多相机暂不共享阴影 atlas |
| 021 | `IsEnabled` 为外部动态开关 + Record guard 契约 | Pass 内部不得写 `IsEnabled`；合法退出为「`AddRenderPass` 前预检 return」与「render func 内 return」；禁止 `AddRenderPass` 后未 `SetRenderFunc` 就 return（执行期抛缺 RenderFunc） |
| 022 | `RenderGraphAsset.ParameterRevision` 驱动运行时重建 | 参数缓存 / 设置修改自增修订号（编辑器经 `SerializedObject` 路径显式 `BumpParameterRevision`）；`CameraRenderer.Build` 比较修订号决定重建，修复"同资源改参数不生效" |
| 023 | 全局 shader 资源绑定下沉到生产者（`IGlobalShaderResource`） | 生产者 Pass 自描述其全局属性 / keyword / 可用条件，消费者（`ForwardPass`）仅遍历已连接输入 slot 的属主通用触发绑定，消除消费者对具体生产者类型与 PropertyID 的硬编码（开闭）；绑定时机仍在消费者 draw 前，保持帧内全局状态确定性；统一 `DrawShadowPass` 原先的自绑做法；发现方式经 ADR-041 改为按显式依赖边 |
| 024 | 级联参数随相机、分辨率随光源 | 级联级数 / 分割 / 更新模式本质由观察者（相机）决定，同一场景多相机可各配级联；分辨率是每光源的显存开销选择。跨相机共享同一套 splits，避免逐光源重复上传 |
| 025 | cascade 选级用深度 + splits，替代裁剪球 | 去掉 `_ShadowCascadeSpheres` 小缓冲与逐级球体测试，改用 `_ShadowCameraDatas`（按方向光槽位索引）与视轴深度判据；球体方案与深度方案在相机视锥内等价（球体 ⊆ 子视锥包围），深度判据省一次缓冲读取且与 C# split 语义严格一致 |
| 026 | 方向光可覆盖相机级联设置 | 默认级联随相机（ADR-024），方向光经 `overrideCameraShadowSettings` 开关用自身级联设置绘制；`_ShadowCameraDatas` 由单元素扩为按方向光槽位索引，`ShadowLightData.cameraDataIndex` 供 shader 选级定位，保证绘制矩阵与 shader 选级严格同源 |
| 027 | 反射探针图集改用 `TextureAllocator` + 多 slice `Tex2DArray` | 取代手写递归四等分布局（`GetOffset` 位掩码）：图集为 Pass 持有的持久 `Tex2DArray`，槽位由 `TextureAllocator` 增量分配（brick 256，单 slice ≤ 2048，最多 2 slice），容量不足时按 `importance` 优先保留；分配结果以全部分配结束后的 `Contains + TryGetResult` 为准（重组会搬移既有块）；数据结构增 `sliceIndex`、参数缓冲的 `atlasSize` 供 shader 按 slice 采样与归一化 padding |
| 028 | 反射探针图集内容按需更新 | 持久图集 + 稳定槽位使内容可跨帧复用：逐探针 `ProbeSlot` 记录槽位 / 源 / 块尺寸 / 有效性，baked·custom 写入一次即复用，实时探针由 `IReflectionProbeUpdateSource`（Phase B 的 `ReflectionProbeRenderer`，以相机池「本帧已渲染面」为准）判定是否重写；「本帧分配过」必须置脏（槽位复用后偏移可能相同）；mip 改为逐级由源 cubemap 投影（级数 `log2(块尺寸) - 2`），去掉每帧整图 `GenerateMips` |
| 029 | 渲染调试的值与文本**全程留在 GPU**，CPU 仅提供元信息 | 值格式化与文本绘制都在片元着色器完成（`RenderDebugManager` 只上传标签 / 类型 / 格式）。规避 `AsyncGPUReadback` 的帧延迟，调试显示与画面同帧；且不引入任何同步点 |
| 030 | 调试字模采用 **256×128 图集 + ASCII 下标**，字模由**内置 5×7 位图程序化生成** | 前半个决策与 HDRP 参考一致：CPU 把标签打包成 `uint[]`（4 字符/uint），shader 解包减 `ASCII_START` 得字块下标 —— HLSL 中不出现字符字面量，扩展字符只需换图集。后半个决策改为程序化生成：Unity 动态字体图集会把部分字形**旋转 90°** 存储且 `CharacterInfo` 无旋转标记，CPU 侧按 UV 拷贝必然错位；内置位图字模零资产、零系统字体依赖，Editor 与 Player 行为一致 |
| 031 | Pass 调试能力经 `IPassDebugProvider` 自描述，宿主统一触发 | 复用 ADR-023 的「自描述 + 宿主遍历触发」哲学：`CameraRenderer` 在 `PreRecord` 后对每个实现者下发一次 `PassDebugSelection`，pass 在自己的 render func 内体现选择（渲染命令必须记录在与绘制同一个命令缓冲上，只有 pass 知道那是不是 `ctx.cmd`）。新增可调试 pass 无需改管线 |
| 032 | 调试用**少 keyword + uniform 通道号**，而非逐通道 keyword | 全局仅一个 `HN_DEBUG_PER_PIXEL` + `_HNRPDebugChannelId`，shader 内 `switch` 选通道，避免逐通道生成变体 |
| 033 | **`DebugDisplayPass` 由管线强制追加，不进模板结构**（修订 ADR-018 边界） | 调试显示是管线级能力而非用户可编排内容：`CameraRenderer.Build` 在 `template.Build()` 之后无条件追加，不写入 `RenderGraphTemplates`、不进 `RenderGraphAsset` 参数缓存与编辑器 pass 面板、不提供 `IsEnabled` 语义。保证任意图（含未来新增模板）自动获得调试能力；`#if UNITY_EDITOR \|\| HNRP_DEBUG_DISPLAY` 保证发布构建零代码。模板结构仍由模板代码唯一生成的约束不变 |
| 034 | 每像素值 → 颜色渐变映射**在生产者的片元着色器内直接混入颜色输出** | 需求是「覆盖原渲染颜色、透明度可配」。生产者直出无需额外全屏 pass、随机写纹理（UAV）或跨 pass 依赖：几何遮蔽天然正确、透明度即 `lerp` 系数、零额外 draw call，也不存在「未写入像素」的哨兵问题 |
| 035 | 渐变以 **256×1 LUT 纹理**实现，色带在 CPU 生成 | 采样成本恒定（一次纹理取样）；改色带只需重建 LUT，不产生 shader 变体；天然支持任意用户自定义控制点（`DebugColorMapSettings.Palette`） |
| 036 | 编译期 `HNRP_DEBUG_DISPLAY` + 运行期 `SupportRuntimeDebugDisplay` 两层开关 | 前者决定调试代码 / 资源是否纳入 Player 构建，后者决定已纳入时运行时是否真的允许生效；Editor 恒纳入且不受运行期开关限制，便于迭代。打包 Debug 模式 = 定义宏 + 勾选开关 |
| 037 | PCSS 软阴影采用**传统 PCSS + 旋转泊松**：atlas 统一为**单张** `R16_UNorm`（无深度附件，`BlendOp Min` 写最近深度，无 mip） | 去掉 VSSM 的矩 / 深度² 与 mip 链：传统 PCSS 只需深度做 blocker 搜索与 PCF，逐 texel 比较不需要 mip 金字塔，故 atlas 单通道、无 mip、软硬同格式（切换不重建 atlas）。旋转泊松盘（16 点 LUT + CoreRP `InterleavedGradientNoise` 每像素旋转）在较少采样下打散去相关带状伪影，替代原 VSSM 的 mip 二分 blocker 搜索。`BlendOp Min` 仍是去深度附件的关键（深度单调，min 等价取最近） |
| 038 | cascade 级间衔接用**噪声随机抖动二选一**，过渡区按分割距离百分比 | 交界处硬切换产生可见接缝；过渡区（本级远端最后 `cascadeBlendPercentage` 比例的分割距离）内用 `smoothstep` 求权重，`InterleavedGradientNoise` 逐像素在相邻两级二选一采样。每像素仍只采一级 cascade，**总采样数不变**（双边插值会使采样翻倍）；噪声为屏幕空间静态（无 TAA 不闪烁）。百分比作为 pass 级全局标量随 `_ShadowMapParamsBuffer` 下发，不按光源区分 |
| 039 | Pass 面板内容由**统一接口 `PassEditor` 自描述**，RenderGraphAsset 面板统一触发；自定义优先声明式布局 | `Pass` 是纯 C# 类，不能用 `[CustomEditor]`，故用 `[PassEditor(typeof(XxxPass))]` + 注册表把类型映射到面板编辑器；`RenderGraphAssetEditor` 展开某 pass 时调 `PassEditor.DrawPassParameters(context)`（即该 pass 自己的绘制代码），新增 pass 的面板无需改面板代码。自定义优先用 `PassFieldLayout` 声明分组/隐藏/条件显示，参数行仍由通用抽屉按 `SerializedProperty` 绘制，避免每个 pass 重复实现 IMGUI；Pass 特异的隐藏/条件知识（如 `RenderOutputPass.flip`）留在该 pass 的编辑器内，通用抽屉不内建具体 Pass 字段黑名单（开闭） |
| 040 | 跨 Pass 信息传递采用 **R / F / G 三通道**，且**契约与载荷归特征所有、核心只拥有传输**：资源语义随句柄（根契约 `IResourceTraits`，特征派生接口如 `IDepthPrepassTraits`）、帧级事实挂上下文（`CameraContext.Facts`，通用状态用强类型字段、生产者特有事实走注册区）、图级设置随模板（`RenderGraphSettings`） | 连接与句柄存在性只表达「资源存在」，不表达「内容为何」；`ZTest Equal` 等决策依赖后者，且句柄可能连到空 / 透传缓冲。若把语义/事实做成中心枚举或聚合容器，会随 pass 种类单调膨胀且耦合所有特征。改为「特征定义契约 + 核心只持引用」后：R 每 slot 仅 1 引用、未声明即 `null`（按需付费），F 未发布即零存储；新增语义/事实不改核心（开闭）。R 实现不可变 → 可长期复用、稳态零分配、可安全共享。整体沿用 ADR-023 / ADR-031 的「生产者自描述 + 消费者通用发现」哲学，不引入全局可变总线；配套规则见 §2.10 |
| 041 | **slot 回归内容，依赖独立成边；全局资源持久化**（修订 ADR-023 / §2.4 / §2.8）：新增 `PassDependency`（name-based，无句柄）表达执行先后 + 生产者可发现性，`RenderGraphBuilder` 注入 `Pass.Dependencies` 并参与拓扑排序；`ConnectedProducerQuery` 改为按 `Dependencies` 发现生产者；`BuildLightData` / `ClusterCullingLight` / `ClusterCullingReflectionProbe` 的全局缓冲、`DrawShadow` 的 atlas/表缓冲全部改为 **Pass 自持持久资源**（`RTHandles.Alloc` / `ValidateComputeBuffer`，`Cleanup` 释放），掩码类新增「本帧已产出」标志替代 slot 句柄重置；`ForwardPass` 删除 LightDatas / ShadowMap / ScreenSpaceShadowMap / ReflectionProbeAtlas / ProbeMask / ProbeDatas / LightMask 共 7 个「伪装成 buffer 的依赖 slot」，只保留 color / depth 链；compute 消费者经新接口 `ILightDatasProvider` 直接引用生产者持久缓冲 | 全局绑定时代 slot 已不传内容（句柄仅用于声明依赖与发现生产者），`builder.ReadComputeBuffer(handle)` 结果被丢弃、纯粹为副作用，语义混乱。让 slot 只表达内容、依赖显式成边后：依赖可读可测、绑定触发点明确、消费者零假 slot；持久化则使全局资源生命周期自主（不依赖消费者的假读取保活），消除「无消费者即被 RenderGraph 回收」的隐式约束 |
| 042 | **屏幕空间阴影用 ComputeShader 合并全部投影光源到一张 mask**：新增 `ScreenSpaceShadowMaskPass`，从显式依赖边发现 `IShadowMapProvider`（`DrawShadowPass`）取图集 + 三张表，从深度 slot 取深度，逐像素遍历 `_ShadowLightDatas` 中 `resolution > 0` 的全部光源（方向光按级联 / 点光按面 / 聚光单张）调用 `Shadow.hlsl` 的 `GetShadowAttenuation` 并相乘合并，输出单通道 `R8_UNorm` UAV mask；深度目标改为纯深度纹理（`ColorFormat = None`）以支持 SRP 采样；`ForwardPass` 经新输入 slot 消费 mask，绑全局纹理 + 开关 `SCREEN_SPACE_SHADOW_MAP`（透明度 pass 未连接 → 自动关闭回退 atlas） | 需求为「所有投影光源绘制到一张屏幕空间 mask」。复用 `Shadow.hlsl` 保证与逐光源 atlas 阴影逐像素一致；生产者自描述 + 依赖边发现沿用 ADR-023/041，不改核心；mask 为 RG transient 内容 slot，遵循 ADR-017/041 的 slot 语义。单通道合并为**近似**（多光源相乘，无法区分逐光源贡献）；如需逐光源精确，可改为按光源槽索引的 `Texture2DArray` |
