# HNRP 架构文档（重新规划版）

> HaoNaN Render Pipeline — 基于 Unity 2022.3 的自定义渲染管线  
> 本文档为全新架构规划，尚未实施。待对齐后开始重构。

---

## 0. 设计目标与原则

| # | 目标 | 原则 |
|---|------|------|
| 1 | **可扩展** — 轻松增加自定义 Pass | Pass 继承纯 C# 基类 + 类型注册表 |
| 2 | **可编排** — 以 Slot 连接 Pass，未来支持可视化编辑器 | 外部化连接配置（name-based），不硬编码连线 |
| 3 | **运行时可变** — 运行时修改管线 / 不同 Camera 不同管线 | Pass 非 ScriptableObject，管线配置可动态替换 |
| 4 | **Camera 隔离** — 每个 Pass 只作用于一个 Camera | 每个 Camera 独立创建 Pass 实例组 |
| 5 | **视图全覆盖** — SceneView / Preview / Reflection 可独立配置 | CameraPipelineConfig 支持所有 CameraType |
| 6 | **配置外部化** — Pass 和管线有独立参数资源 | PassConfigBase ScriptableObject 子类化 |

### 关键变化 vs 旧架构

| 旧设计 | 新设计 |
|--------|--------|
| Pass 继承 ScriptableObject | Pass 继承纯 C# 抽象类 |
| 连线通过 index (Slot.Connect) | 连线通过 name，记录在 RenderGraphAsset 中 |
| 管线定义写在 Standard/Preview.cs 代码中 | 管线定义是 RenderGraphAsset 资源 |
| 所有 Camera 共享同一组 Pass 实例 | 每 Camera 独立创建 Pass 实例组 |
| 管线由 PipelineAsset 的 ViewBlock 选择 | 管线由 Camera 的 CameraPipelineConfig 字段选择 |
| HNRenderGraphBase 负责一切 | 职责分离给 CameraRenderer + RenderGraphAsset |
| 运行时不可变, Editor 预置 | RenderGraphAsset 是静态模板, CameraRenderer.passes 是运行时可变列表 |

## 2. 核心组件详解

### 2.1 管线资产层

```
HNRenderPipelineAsset
├── defaultGameViewConfig: CameraPipelineConfig
├── defaultSceneViewConfig: CameraPipelineConfig    (Editor only)
├── defaultPreviewConfig: CameraPipelineConfig       (Editor only)
├── defaultReflectionConfig: CameraPipelineConfig
└── 全局常量: MAX_DIRECTIONAL_LIGHT_ON_SCREEN, MAX_LOCAL_LIGHT_ON_SCREEN

→ CreatePipeline() → HNRenderPipeline
```

**CameraPipelineConfig** (ScriptableObject)：
```
每 Camera 的管线分配资源
├── renderGraph: RenderGraphAsset    — 指向具体的管线图定义
└── (可扩展: override settings, quality tier 等)
```

**使用方式**：
- PipelineAsset 提供默认配置（按 CameraType）
- `HNAdditionalCameraData` 上可覆写 `pipelineConfig` 字段，为空则使用默认
- 运行时替换 `pipelineConfig` 即可切换管线

```csharp
// 示例：运行时切换 Camera 的管线
var cameraData = camera.GetHNRPAdditionalCameraData();
cameraData.PipelineConfig = Resources.Load<CameraPipelineConfig>("Configs/CustomPipeline");
```

### 2.3 模板与实例

`RenderGraphAsset` （ScriptableObject）是**静态模板**，`CameraRenderer` 的 `passes`（`List<Pass>`）才是**运行时实例**。

```
RenderGraphAsset (ScriptableObject, 磁盘上的模板.asset)
    ├── PassDefinition[]    ← 描述"需要哪些 Pass"
    ├── SlotConnection[]    ← 描述"Pass 之间如何连线"
    └── RenderGraphSettings ← 管线级公用参数
            │
            │  CameraRenderer 构建时读取（每 Camera 一组）
            ▼
CameraRenderer.passes (List<Pass>, 纯运行时 C# 对象)
    ├── 独立的 Pass 实例，可运行时增删改
    ├── Connect() 后的 Slot 关系
    └── 所属 Camera 的 CameraContext
```

**关键区别**：

| | RenderGraphAsset | CameraRenderer.passes |
|---|---|---|
| 存储位置 | 磁盘 `.asset` | 内存 |
| 可运行时修改 | ✅ 可以，但修改的是资产本体 | ✅ 可以，且不影响其他 Camera |
| 修改持久化 | Editor Save 后；Build 不可 | 不持久，帧间持续 |
| 共享性 | 被多个 Camera 引用 | 每个 Camera 独立 |
| 用途 | Editor 中编排管线 | 运行时执行渲染 |

**常见操作的正确路径**：

```csharp
var camRenderer = camera.GetComponent<CameraRenderer>();
// 或通过 HNRenderPipeline 获取

// ✅ 运行时临时开关 — 操作 CameraRenderer
camRenderer.SetPassEnabled("Bloom", false);

// ✅ 运行时动态插 Pass — 操作 CameraRenderer
var debugPass = PassRegistry.Create("DebugOverlayPass");
camRenderer.InsertPass(3, debugPass, new SlotConnection[] { ... });

// ✅ 永久修改管线结构 — 修改 RenderGraphAsset 资产
asset.passes.Add(new PassDefinition { passType = "SSAOPass", ... });
// Editor: AssetDatabase.SaveAssets();
// Build:  无法持久化，但可作为初始值

// ✅ 一劳永逸换管线 — 换 CameraPipelineConfig
cameraData.PipelineConfig = Resources.Load<CameraPipelineConfig>("BossFightPipeline");

// ✅ 两个 Camera 用同一模板 → 各自有独立 Pass 列表
var rendererA = new CameraRenderer(cameraA, standardAsset);  // 读同一模板
var rendererB = new CameraRenderer(cameraB, standardAsset);  // 读同一模板
// rendererA.passes ≠ rendererB.passes，互不影响
```

### 2.4 Pass 系统

#### Pass 基类

```csharp
public abstract class Pass
{
    // 元数据（由 RenderGraphAsset 设置）
    public string Name { get; internal set; }
    public bool IsEnabled { get; set; }

    // 配置（由 PassDefinition 注入）
    public PassConfigBase Config { get; internal set; }

    // Camera 上下文（由 CameraRenderer 注入）
    public CameraContext Context { get; internal set; }

    // Slot 管理
    protected Dictionary<string, PassSlot> inputSlots  = new();
    protected Dictionary<string, PassSlot> outputSlots = new();
    public IReadOnlyDictionary<string, PassSlot> InputSlots  => inputSlots;
    public IReadOnlyDictionary<string, PassSlot> OutputSlots => outputSlots;

    // ── 注册 Slot（子类在构造函数或 SetupSlots 中调用） ──
    protected TextureSlot AddInputTexture (string name);
    protected TextureSlot AddOutputTexture(string name);
    protected ComputeBufferSlot AddInputComputeBuffer (string name);
    protected ComputeBufferSlot AddOutputComputeBuffer(string name);
    protected RendererListSlot AddInputRendererList (string name);

    // ── 获取 Slot ──
    protected T GetSlot<T>(string name) where T : PassSlot;

    // ── 生命周期 ──
    /// <summary>创建 Slot，注册子类必需的 Slot。在实例化后立即调用。</summary>
    public virtual void SetupSlots() { }

    /// <summary>从 Config 初始化参数。</summary>
    public virtual void Initialize() { }

    /// <summary>在 RenderGraph.RecordAndExecute 内录制。</summary>
    public abstract void Record(RenderGraph renderGraph);

    /// <summary>每个 Pass 独立拥有的中间资源清理。</summary>
    public virtual void Cleanup() { }
}
```

#### PassSlot 类型

```
PassSlot (abstract)
├── TextureSlot        — produces/consumes TextureHandle
├── ComputeBufferSlot  — produces/consumes ComputeBufferHandle
└── RendererListSlot   — produces/consumes RendererListHandle (仅 Input)

每个 Slot 包含:
├── Name        — 在 Pass 内唯一
├── Direction   — Input / Output
├── IsConnected — 是否已连接
├── Handle      — 运行时资源 Handle (仅 Output 端设置)
└── ConnectedSlot — 指向对端 Slot (由 SlotResolver 设置)
```

#### Slot 的 Handle 传递

```
Phase 1: 解析连接
  cameraRenderer 创建 Pass 列表 → SlotResolver 根据 SlotConnection 设置 pair

Phase 2: 录制 (RecordAndExecute scope 内, 按拓扑序)
  PassA.Record:
    outputSlotA.Handle = renderGraph.CreateTexture(desc)  ← 创建资源
    renderGraph.AddRenderPass(...)                          ← 注册 Pass

  PassB.Record:
    inputSlotB.ConnectedSlot.Handle                        ← 获取 PassA 创���的 handle
    builder.UseColorBuffer(inputSlotB.ConnectedSlot.Handle) ← 使用
```

#### 自定义 Pass 示例

```csharp
// 新增一个 Pass 只需三步:
// ① 创建类继承 Pass
public class MyCustomPass : Pass
{
    protected override void SetupSlots()
    {
        AddInputTexture("color");
        AddOutputTexture("result");
    }

    protected override void Initialize()
    {
        // 从 Config 读取参数
    }

    protected override void Record(RenderGraph renderGraph)
    {
        var input = GetInputTexture("color");
        var output = GetOutputTexture("result");

        output.Handle = renderGraph.CreateTexture(...);

        using (var builder = renderGraph.AddRenderPass<MyData>("MyPass", out var data))
        {
            data.input = builder.ReadTexture(input.Handle);
            builder.WriteTexture(output.Handle);
            builder.SetRenderFunc((data, ctx) =>
            {
                // 实际渲染逻辑
            });
        }
    }
}

// ② 注册
PassRegistry.Register<MyCustomPass>("MyCustomPass");

// ③ 在 RenderGraphAsset 中添加 PassDefinition 和连线即可使用
```

### 2.5 CameraRenderer — 单 Camera 渲染器

`CameraRenderer` 是 Pass 图运行的宿主。它持有当前 Camera 独立的 Pass 实例列表和 CameraContext。

```csharp
public class CameraRenderer
{
    // ── 构造 ──
    public CameraRenderer(Camera camera, RenderGraphAsset template);

    // ── 属性 ──
    public Camera Camera { get; }
    public CameraContext Context { get; }
    public IReadOnlyList<Pass> Passes { get; }  // 只读视图
    public RenderGraphAsset SourceTemplate { get; } // 来源模板（可能为 null）

    // ════════════════════════════════════════════════════
    //  运行时 Pass 修改 API（操作的是 passes 列表）
    // ════════════════════════════════════════════════════

    /// <summary>追加一个 Pass 到末尾，并建立到已有 Pass 的 Slot 连接。</summary>
    public T AddPass<T>(string instanceName, params SlotConnection[] connections) where T : Pass, new();
    public Pass AddPass(Type passType, string instanceName, params SlotConnection[] connections);

    /// <summary>在指定位置插入 Pass。</summary>
    public T InsertPass<T>(int index, string instanceName, params SlotConnection[] connections) where T : Pass, new();

    /// <summary>移除 Pass 并断开相关连接。返回被移除的 Pass。</summary>
    public Pass RemovePass(string instanceName);

    /// <summary>按名称查找 Pass。</summary>
    public T FindPass<T>(string instanceName) where T : Pass;

    /// <summary>设置 Pass 的开关状态。</summary>
    public void SetPassEnabled(string instanceName, bool enabled);

    /// <summary>在两个已有 Pass 之间插入新连接。</summary>
    public void Connect(
        string sourcePass, string sourceSlot,
        string targetPass, string targetSlot);

    /// <summary>断开指定连接。</summary>
    public void Disconnect(
        string sourcePass, string sourceSlot,
        string targetPass, string targetSlot);

    /// <summary>清空所有 Pass 和连接，可选重新从模板构建。</summary>
    public void Reset(RenderGraphAsset newTemplate = null);

    /// <summary>将当前 passes 状态快照保存为新 RenderGraphAsset（Editor only）。</summary>
    public RenderGraphAsset SnapshotToAsset(string savePath); // #if UNITY_EDITOR
}
```

**AddPass / InsertPass 的 Connection 参数说明**：

运行时动态添加 Pass 时，必须同时声明它如何接入现有 Pass 图。`SlotConnection` 的 `sourcePass` / `targetPass` 可以引用已有 Pass 的实例名：

```csharp
// 示例：在不透明 Pass 之后插入一个描边 Pass
var connections = new[]
{
    new SlotConnection
    {
        sourcePass = "forwardOpaque",  // 已有 Pass 的输出
        sourceSlot = "color",
        targetPass = "outlinePass",    // 新 Pass 的输入
        targetSlot = "colorInput"
    },
    new SlotConnection
    {
        sourcePass = "forwardOpaque",
        sourceSlot = "depth",
        targetPass = "outlinePass",
        targetSlot = "depthInput"
    }
    // ... 还需要一条从 outlinePass 输出到 sky Pass 输入的连接
    // 这条因为 sky 还不认识 outlinePass，可以在 Connect 后单独 Connect()
};

var outline = renderer.AddPass<OutlinePass>("outlinePass", connections);
// 再做下游连接
renderer.Disconnect("forwardOpaque", "color", "sky", "colorInput");
renderer.Connect("outlinePass", "colorOutput", "sky", "colorInput");
```

**渲染流程**：

```csharp
public void Render(ScriptableRenderContext renderContext, RenderGraph renderGraph)
{
    // 1. Culling
    if (!Camera.TryGetCullingParameters(out var cullingParams)) return;
    context.CullingResults = renderContext.Cull(ref cullingParams);
    context.VisibleLights = context.CullingResults.visibleLights;
    context.VisibleReflectionProbes = context.CullingResults.visibleReflectionProbes;

    // 2. 全局状态
    UpdateGlobalConstantBuffer(renderContext);
    UpdateGlobalKeywords();

    // 3. RecordAndExecute
    using (renderGraph.RecordAndExecute(new RenderGraphParameters
    {
        executionName = Camera.name,
        currentFrameIndex = context.FrameCount,
        rendererListCulling = true,
        scriptableRenderContext = renderContext,
        commandBuffer = context.Cmd
    }))
    {
        // 拓扑序执行
        var ordered = TopologicalSorter.Sort(passes);
        foreach (var pass in ordered)
        {
            if (!pass.IsEnabled) continue;
            pass.Record(renderGraph);
        }
    }

    // 4. 清理
    CommandBufferPool.Release(context.Cmd);
    foreach (var pass in passes) pass.Cleanup();
}
```

**注意**：动态增删 Pass 会触发内部重建连接拓扑（`RebuildSlotConnections`），因此 `AddPass` / `RemovePass` 开销非零，不应在每帧高频调用。推荐在事件驱动的时机（场景加载、状态切换）调用。

### 2.7 SlotResolver — 连接解析器

```csharp
internal static class SlotResolver
{
    public static void Resolve(
        List<SlotConnection> connections,
        List<Pass> passes)
    {
        var passMap = passes.ToDictionary(p => p.Name);

        foreach (var conn in connections)
        {
            var sourcePass = passMap[conn.SourcePass];
            var targetPass = passMap[conn.TargetPass];

            var sourceSlot = sourcePass.OutputSlots[conn.SourceSlot];
            var targetSlot = targetPass.InputSlots[conn.TargetSlot];

            // 双向链接
            sourceSlot.ConnectTo(targetSlot);
        }
    }
}
```

```
  wireOverlay.color           → finalBlit.color

拓扑序:
  1. buildLight         (无依赖)
  2. clusterProbe       (无依赖)
  3. clusterLight       (依赖 buildLight)
  4. colorInput         (无依赖)
  5. depthInput         (无依赖)
  6. forwardOpaque      (依赖 colorInput, depthInput, buildLight, clusterProbe, clusterLight)
  7. sky                (依赖 forwardOpaque)
  8. transparency       (依赖 sky)
  9. wireOverlay        (依赖 transparency)
  10. finalBlit         (依赖 wireOverlay)
```

## 9. 设计决策记录 (ADR)

| ADR | 决策 | 理由 |
|-----|------|------|
| ADR-001 | Pass 为纯 C# 类（非 ScriptableObject） | 支持运行时创建/销毁；支持按 Camera 独立实例化 |
| ADR-002 | 管线图配置外部化为 RenderGraphAsset (ScriptableObject) | 方便修改；支持未来可视化编辑器；配置与代码分离 |
| ADR-003 | Pass 连线使用字符串名称匹配 | 编辑器友好；更容易理解和调试 |
| ADR-004 | 每 Camera 独立 CameraRenderer | 状态隔离，解决多 Camera 共享数据 bug |
| ADR-005 | 使用 Unity RenderGraph 模块 | 自动资源生命周期管理、Pass 裁剪 |
| ADR-006 | Pass 通过 CameraPipelineConfig 分配 | 运行时不同 Camera 可使用不同管线 |
| ADR-007 | PassConfigBase 为独立 ScriptableObject | 参数设置独立于管线定义，可复用 |
| ADR-008 | Cluster Culling 替代 Forward+ Tile | 更精细的 Z 轴裁剪 |
| ADR-009 | Reflection Probe Octahedral → 2D Atlas | 避免 Cubemap 采样开销，支持 Mip |
| ADR-010 | GlobalConstantBuffer 统一管理 | 减少 SetGlobal 调用，Batch 友好 |
| ADR-011 | RenderGraphAsset 是模板, passes 是实例 | ScriptableObject 定义结构，CameraRenderer 复制并独立运行 |

## 10. 迁移路径

1. **Phase 1** — 新建核心框架：`Pass`, `PassSlot`, `PassRegistry`, `RenderGraphAsset`, `CameraPipelineConfig`, `CameraContext`, `CameraRenderer`
2. **Phase 2** — 逐个迁移现有 Pass（`BuildLightDataPass` → → `RenderOutput`），每个 Pass 改为继承 `Pass`，内部 Record 逻辑尽量不变
3. **Phase 3** — 创建 RenderGraphAsset 资源（Standard.asset, Preview.asset 等）替代 `Standard.cs` / `Preview.cs`
4. **Phase 4** — 重构 `HNRenderPipeline.cs`，用 `CameraRenderer` 替代 `PrepareRenderRequests` + `ExecuteRenderRequests`
5. **Phase 5** — 重构 Editor（Pass Editor、RenderGraphAsset Inspector）
6. **Phase 6** — 移除废弃文件

每个 Phase 完成后应保持项目可编译、可渲染。
